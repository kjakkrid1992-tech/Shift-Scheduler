# Phase 6A — historical archive pilot
Apply migration 01000 after 00900. Adds three owner-only tables. Run supabase/tests/legacy_payroll.sql with an active owner, manager and existing test employee; synthetic changes rollback. Download development-v2; log in as owner, open ประวัติ Excel. Select prepared local JSON (format baanjergun-legacy-payroll-v1), review every row, select intended rows, confirm. No raw workbook parser in browser; conversion is local. Never upload private JSON or workbook to GitHub. Source sheet/row identifies the canonical historical workbook; same location changed is blocked, identical content at different location blocked for manual review. Exact retries skipped. Batch atomic, 300 records maximum; archive UI maximum 999. Fingerprint is duplicate detection only, not cryptographic proof. Source SHA is supplied by converter, not independently verified by server. Dates are preserved as text, not certified payment dates.
Archive is separate from live payroll; no employee/employment/rate, attendance, advance, tax/YTD, or payment records are automatically created. Owner manually links existing employee after review; can unlink/relink with reason and revision log. Group or unclear slips should remain unlinked. No split allocation, official payslip generation or corrections to archived source in this release. Bank accounts, annual totals, signatures, formulas and original formatting not stored; keep original Excel secure. Future Phase 6B: reviewed employee master and employment/rate migration, resolve group records and annual definitions. Verify against workbook and browser before production. No real payroll data in repo.
