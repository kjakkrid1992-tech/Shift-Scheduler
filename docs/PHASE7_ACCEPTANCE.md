# RC1 — consolidated acceptance and go-live gates
## Install once
Latest development-v2 ZIP; retain local v2/config.js (project URL + publishable key only). No service-role key, DB password, workbook, JSON or dump in Git. Use a separate pilot or verified restored clone, never real payroll for synthetic testing. Install only missing migrations, in ascending order: 01000 legacy archive; 01100 legacy staff; 01200 bulk attendance/reporting; 01300 correction requests; 01400 payroll adjustments. If 00900 and earlier were applied, do not rerun. 7.7–7.8 layout and preflight need no additional migration. Business tables expected: 27. SQL tests separately run in transaction and rollback; do not concatenate multiple scripts into one transaction. preflight_readonly.sql contains read-only catalog/aggregate checks; run after schema tests. Expect 27 expected business tables, NONE missing/RLS-disabled/anon grants/direct staff financial writes, and investigate publicly executable security-definer functions (some unrelated provider functions may be legitimate). Counts of real current staff and archived slips are reconciliation targets, not assertions.
## Browser acceptance on synthetic data
1. Owner/Manager login, logout and permission denial; open each tab, inspect console; two concurrent browsers; stale data, revision and source lock checks.
2. Staff: verify current 5 people, manually confirm identity, department, employment dates, pay type and rates. No date/rate guesses. Former staff use verified end dates; master-only identity is not current employment. Review historical records; no automatic staff updates.
3. Calendar: period 26–25, choose date, edit, save/reload, confirm, list/print, mobile. Attendance: completed matches, past off, manual exceptions, combined shifts, atomic bulk save/verify/owner approve, stale revisions and failed batch.
4. Cash advance: draft, approval, payment, cancellation/void, residual allocation and duplicate prevention. Payroll: known wage/OT and manual categories, draft, evidence, final close, payment, print, immutable records. Correction: request/review, original paid first, approve separate nonzero net adjustment, record actual cash/transfer with evidence, reject duplicate, cancel unsettled only, cap voluntary return. No automatic deductions, original payment metadata changes, or correction of unpaid final. Never approve a negative delta without actual voluntary return/legal review. Net-only correction does not recalculate tax/social security or change advance allocation; accounting review required.
5. Archive: local prepared JSON preview/import/retry; compare 208 source records if all selected; bulk name links only after verification; 38 unnamed or group records remain unresolved until attribution known; owner-only archive. No original workbook uploaded to Git.
6. Dashboard and profile: compare approved hours, draft/final/paid amounts, yearly totals by paid date, separate cash adjustments and Excel. YTD is not tax reporting.
7. Desktop/mobile keyboard usability, print, error paths, missing schema, browser session timeout, duplicate submissions.
## Backup and security
- Before any migration or live cutover, make a provider-supported full backup including auth and all application schemas/configuration; verify retention/access and restore into isolated environment. Availability varies by project/plan; check project dashboard. Do not assume a backup exists.
- Optional Windows scripts/backup-public.ps1 uses installed PostgreSQL client tools and PGHOST/PGPORT/PGUSER/PGDATABASE/PGSSLMODE with protected credentials; output outside repository, restricted/encrypted storage. It exports public schema only and checks archive catalog + SHA256, NOT a full backup, NOT a restore drill. It omits auth, staff_private, storage and platform configuration. Do not restore over live database. Use full provider-supported restore or a documented clone to test login, roles, counts, payroll and archive; record result and recovery time. Do not share connection strings, passwords or dumps.
- Verify private signup disabled, unique Owner/Manager accounts, strong passwords/MFA where supported, no shared credentials; least privilege, RLS/RPC tests, sensitive archives owner-only. Browser config must contain publishable key only. Keep original Excel and backup private; do not include real personal data in issue screenshots. Verify repository visibility and revoke any exposed secrets.
- Reconcile one actual pay cycle in parallel with Excel, manual approval of wage/deduction rules and taxes, prepare correction policy for unsupported cases, record sign-off before using real closure/payment. No automatic backup, restore, real roster update, data import, deployment or production approval performed by code commit.
